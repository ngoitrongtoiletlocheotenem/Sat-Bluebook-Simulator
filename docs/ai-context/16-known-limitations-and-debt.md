## Implemented limitations

| Limitation                                       | Evidence and consequence                                                                                                                                                                                                                                                            |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cross-device stale writes                        | [Player](../../client/Player.tsx) ownership lease is browser-local. [attemptSaveSchema](../../server/attempts.ts) has no expected revision and shared `Attempt` omits revision. SQL serialization prevents overlapping transitions, not lost updates from sequential stale clients. |
| Recovery is best effort                          | localStorage pending edits require available storage, same browser and an accepting module. Closing before persistence, clearing storage or reconnecting after a strict deadline can lose unsaved edits. There is no IndexedDB/service-worker offline engine.                       |
| Timing is not proctoring                         | Server controls module deadlines; client-reported per-question elapsed time is not trusted evidence of attention. No proctoring or device-wide exam ownership service is present.                                                                                                   |
| Blueprint history is not independently versioned | [saveBlueprint](../../server/blueprints.ts) overwrites config and increments a number. Started attempts snapshot config, but old uninstantiated blueprint revisions cannot be queried.                                                                                              |
| Some history is intentionally live               | Error-list taxonomy filters use current question columns while displayed error content comes from the original version. Report creation overlays current question status/owner metadata before storing the result. This is not a universal event log of all account changes.        |
| Public image URLs                                | Authenticated asset listing is owner-only, while `/uploads` is public static serving. No delete/garbage-collection API, quota system or asset-to-question reference accounting exists. Unused uploads can accumulate.                                                               |
| Remote figure availability                       | Server validates supported URL shape but never downloads remote images. Browser image loading is affected by availability and response policies; a preview succeeding today is not an archival guarantee.                                                                           |
| Import format scope                              | ExcelJS structured worksheet parsing is not OCR/PDF extraction or interpretation of arbitrary workbook layouts. Unreadable files need a correct format or manual entry. Manual row-image repair cannot fix unrelated missing answers/licenses/taxonomy.                             |
| License validation is syntactic                  | A license must be supplied; omitted source defaults to `User authored`, while explicitly empty source fails. These nonempty values do not prove legal permission. Operators/authors must verify rights; do not synthesize provenance.                                               |
| Editable taxonomy and static quotas differ       | Database taxonomy drives validation/analytics, but `quotaCounts` uses static `DOMAINS` and fixed standard allocations. Editing SQL percentages or adding domains does not automatically update full-test assembly quotas.                                                           |
| Report/journal presentation gaps                 | Saved report JSON retains highlights/attached notes, but current report review does not redraw them. General response notes are shown. Journal `note` is accepted/stored by the API but absent from its DTO/UI; `due_at` does not drive a due-review queue.                         |
| Import job recovery and row labels               | SQL preview jobs persist, but the UI has no job list/resume after refresh. Preview labels are parsed-array index + 2 after blank-row removal, so they need not be physical XLSX row numbers. Cancelling repair can leave already-uploaded files.                                    |
| Error status handling                            | The generic error handler can serialize middleware/static errors such as JSON-body 413 or a missing uploaded-file 404 as HTTP 500. Documented error responses are not a complete preservation of underlying status codes.                                                           |
| No email recovery system                         | Registration/login/admin management exist; password-reset email, email verification and MFA flows were not found in the auth/API/client surface.                                                                                                                                    |
| No semantic tutor/memory                         | Tutor uses existing answer feedback; recommendations are heuristics over SQL results. There is no LLM, embedding store or automatic academic-content generation.                                                                                                                    |
| Numeric tolerance is fixed                       | [gradeAnswer](../../server/engines.ts) uses fixed relative tolerance `1e-7`; there is no per-question authored tolerance contract.                                                                                                                                                  |

Question editing also has a stale-form limitation: `updateQuestion` compares the head read during the save request, not the editor's submitted version. An older open form can replace newer content as another version. The previous version rows remain intact; the CAS is not complete editor-level optimistic concurrency.

## Operational limitations

SQLite uses one pooled connection and WAL. The per-attempt Promise queue lives inside one Node process; the misleading `BEGIN IMMEDIATE` comment is not an explicit transaction mode in code. Do not assert safe horizontal SQLite scaling. PostgreSQL uses `FOR UPDATE` for attempt mutations and a pool of up to ten connections, but deployment still needs shared uploads, consistent environment/clock configuration, reverse proxy and a rate-limit strategy beyond per-process memory.

Startup migrates and may seed/bootstrap according to environment settings. Dockerfile defaults sample seeding off; Compose defaults it on unless overridden. There is no dedicated automated backup/restore program in the repository; database and uploads must be backed up coherently by operators. Local smoke writes a report and may create/delete an administrator login session; the Desmos smoke starts an isolated database. Do not treat smoke scripts as read-only checks against live user state.

Broad question selection/import/report processing includes in-memory work; no large-bank benchmark, queue worker or streaming import design was verified. Rate limits are present but no measured load capacity is claimed.

## External dependencies and untested areas

- Desmos needs operator entitlement/configuration and external network availability. No live entitlement/network smoke was repeated for this documentation task. Keep key values out of docs; build-time configuration requires rebuilding the client.
- Default estimated scoring and configurable correctness routing have no official College Board calibration. Exact-form mappings are an extension point, not proof of validated psychometrics.
- PostgreSQL/Docker support is implemented in schema/configuration; no live PostgreSQL, container deployment, backup restore or multi-instance load test was performed in this task.
- Existing accessibility controls and browser tests are not a full accessibility audit, screen-reader certification or complete mobile/browser matrix.
- This task ran lint, typecheck and 25 backend tests. Full browser suite, fresh production build, live Desmos smoke, production smoke and npm audit were not rerun. See [dated evidence](12-testing-verification.md).

## Future opportunities, not implemented behavior

Explicit server revision/lease contracts could resolve cross-device conflicts. Asset lifecycle/private delivery, streaming imports, structured learning events and durable scheduling could support growth. Accessibility, PostgreSQL concurrency, restore drills and load tests would improve operational evidence. These require design and tests; they are not existing modules or promises in this pack.
