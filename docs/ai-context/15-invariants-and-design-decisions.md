# 15. Invariants and design decisions

[Context index](README.md)

These rules follow current implementation. They are not a claim that the system prevents every concurrent or malicious operation. Known enforcement limits are explicit below and in [limitations](16-known-limitations-and-debt.md).

| Rule                                                                           | Why it exists                                                                                                      | Primary enforcement                                                                                            | What breaks if violated                                                        |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Server deadlines decide whether saves are accepted                             | Browser clocks, refresh and offline duration must not grant extra full-test time                                   | [attempts.ts](../../server/attempts.ts): `synchronizeAttempt`, `saveAttempt`, `closeModule`                    | Late answers alter closed work or offline users get extra time                 |
| Synchronize before accepting attempt mutations; reject nonactive/stale modules | A response queue may outlive its module                                                                            | attempts save/finish/tutor/pause paths and [attempt-lock.ts](../../server/attempt-lock.ts)                     | Old autosave overwrites a later module or a transition scores twice            |
| Close/route/activate/score under the attempt transaction/lock                  | A submission can race the timer or another request                                                                 | `withAttemptLock`; PostgreSQL row lock; SQLite single connection                                               | Partial transitions, duplicate response installations or inconsistent scores   |
| Full SAT cannot be paused                                                      | Strict timing differs from practice                                                                                | `pauseAttempt` checks `mode === 'full'`                                                                        | Full mode becomes a customizable untimed assessment                            |
| Question content changes append a version                                      | Started work and error review must preserve original content/answers                                               | [questions.ts](../../server/questions.ts): `updateQuestion`, version CAS + insert transaction                  | Reports and annotations point at altered text; prior answers grade differently |
| Attempts retain assembled form/question-version/scoring configuration          | Later bank, blueprint or scoring changes must not rewrite a started form                                           | `createAttempt` snapshot; response `version_id`; [scoring.ts](../../server/scoring.ts)                         | Route alternatives or scores change mid-attempt                                |
| Stored results are returned without silent rescoring                           | A historic result is evidence of that attempt/model                                                                | attempts `scoreResult` existing-row guard and `getResult`; `score_results` PK                                  | History changes after deployment without an explicit migration                 |
| Supplied form mappings must match exact IDs and versions                       | A conversion for one form is not valid for another                                                                 | `FormMappingScoringEngine`; full-mode upfront route checks                                                     | Unrelated content receives a misleading score mapping                          |
| Unrevealed attempt questions omit answers/explanations/rationales              | Normal assessment delivery must not disclose answer keys                                                           | attempts `redacted`; tutor feedback separate                                                                   | Client can obtain answers during ordinary testing                              |
| Authorization is a server boundary                                             | Client routes, role labels and scope fields are editable                                                           | [auth.ts](../../server/auth.ts), [app.ts](../../server/app.ts), questions/attempt services                     | Account data or bank content crosses ownership boundaries                      |
| Student writes remain private; private questions are owner-filtered            | Private bank material belongs to its author                                                                        | questions `questionQuery`, `createQuestion`, `updateQuestion`; import scope validation                         | Client-crafted requests publish private material or expose another user's bank |
| Registration does not accept a staff role                                      | Public signup cannot confer privileges                                                                             | auth registration schema/create path; admin-only user update                                                   | Privilege escalation                                                           |
| Session tokens stay in HttpOnly cookies, not browser storage                   | Recovery storage must not become a reusable login credential store                                                 | auth session cookie/hash; [api.ts](../../client/api.ts) CSRF handling                                          | Stored-content XSS can steal long-lived account credentials more easily        |
| Mutating cookie-auth requests require CSRF and allowed origin checks           | Cookie possession alone does not authorize another site's POST                                                     | auth middleware and route ordering                                                                             | Cross-site modification                                                        |
| Sanitize rich HTML on input and render                                         | Imported/authored content is untrusted                                                                             | [validation.ts](../../server/validation.ts) sanitize-html; [RichText.tsx](../../client/RichText.tsx) DOMPurify | Stored script/unsafe markup reaches learners                                   |
| Keep Desmos evaluation permission inside its sandbox document                  | External calculator code requires capabilities the main app does not                                               | app CSP routes; [Calculator.tsx](../../client/Calculator.tsx); bridge source checks                            | Main app CSP is weakened or messages can initialize the wrong frame            |
| Browser pending state is recovery, SQL is authoritative                        | Local state can be stale, lost or outside deadline                                                                 | [Player.tsx](../../client/Player.tsx) reconciliation; server save validation                                   | Replay bypasses timing/ownership or users believe unsaved work is durable      |
| Row-image repair changes images only                                           | A manual figure attachment must not alter academic content or duplicate/scope decisions                            | [imports.ts](../../server/imports.ts): `patchImportImages`; strict PATCH schema                                | Fixing a path rewrites answers, explanations or license data                   |
| Confirm rechecks local image availability                                      | A file may disappear between preview and import                                                                    | imports image validation/confirmation; [import-images.test.ts](../../server/tests/import-images.test.ts)       | Valid-looking rows import broken local figures                                 |
| Server does not fetch arbitrary remote figure URLs                             | An import should not turn the server into a remote URL fetcher                                                     | imports validates URLs/local files; browser displays HTTPS previews                                            | Added fetching creates unreviewed SSRF/network behavior                        |
| Upload validation includes bytes, not only extension/MIME                      | Filenames and declared content types are untrusted                                                                 | app image signature detection, size/count limits, metadata-failure cleanup                                     | Executable/unsupported uploads or orphaned failed writes                       |
| License is required; source must be nonempty after defaulting                  | Omitted source defaults to `User authored`; an explicitly empty source fails, and a license must still be supplied | question schema and import preview validation                                                                  | Unknown rights become apparently approved content                              |
| Full forms maintain six disjoint pools and standard module dimensions          | Alternative routes must not repeat items and custom structure needs its own mode                                   | [blueprints.ts](../../server/blueprints.ts) schema; engines assembly; attempts                                 | Routes overlap, counts/times drift or custom tests are mislabeled full SAT     |
| Estimated scores and internal knowledge levels retain clear labels             | No official calibration is established by the code                                                                 | engines/scoring labels; Report                                                                                 | Users mistake an internal approximation for an official SAT result             |

## Decisions with important limits

- **Question versioning is not blueprint version history.** Blueprints increment a counter and overwrite their current configuration. Attempts preserve their own configuration snapshot. Do not infer a nonexistent `blueprint_versions` table.
- **Question edit CAS is not attempt edit CAS.** Question updates compare the head read during the request, not the editor's submitted version; a sequential stale form can still replace content as a new version. Attempt saves increment a revision counter but do not accept an expected revision; serialized cross-device writes can overwrite a response.
- **Attempt redaction is not anti-cheating isolation.** The self-study question-library endpoints expose answers and explanations to students. The redacted attempt payload is a delivery contract, not a guarantee that the same learner cannot consult the bank.
- **A browser lease is not an account-wide lock.** localStorage/storage events and optional browser locks coordinate compatible same-origin tabs. They do not coordinate separate devices or every browser profile.
- **SQLite transaction safety is not a distributed lock.** The queue is process-local; source does not explicitly request `BEGIN IMMEDIATE`. PostgreSQL has row locking, but shared storage and other per-process concerns remain.
- **Question asset ownership is metadata ownership.** `/uploads/*` bytes are publicly readable by URL. Do not tell users the URL is private merely because `/api/assets` is owner-filtered.
- **Version immutability is a service convention.** There is no database trigger preventing an operator from editing historical JSON directly. Avoid direct SQL shortcuts in feature code.

## Modification checklist

When a change touches any rule, inspect its service and the relevant integration/browser test before implementation. Preserve server rejection behavior, historical content and saved-result semantics; update [state](07-state-memory-persistence.md), [security](09-api-auth-security.md), this chapter and [AGENT_MEMORY.md](../../AGENT_MEMORY.md) if the contract intentionally changes. Do not change behavior merely to make older prose accurate.
