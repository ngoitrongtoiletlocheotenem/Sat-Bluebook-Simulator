## Annotation and elimination controls

Highlights & Notes starts off. Students turn it on with the header button; a black underline and pale blue background indicate active mode. Selecting passage or question prose opens the floating formatting palette only while this mode is active. Clicking the header again turns it off, closes the tools and hides the notes panel while preserving saved annotations. Refresh starts with the mode off again. Its three circular pastel swatches apply yellow, blue, or pink highlighting. The underline menu offers solid, dashed, dotted, and None; the trash button deletes the annotation. The folded-note button opens an autosaving note card in a gray side panel beside the passage, with the highlighted excerpt in the card's colored header. Additional annotations can have their own cards. Deleting a note removes the note attachment while preserving its highlight. Clicking a saved highlight reopens its formatting controls.

The notes panel remains hidden until a student attaches a note to selected text. Highlighting alone or pressing the header button before adding a note does not open an empty panel. Turning the mode on can reopen existing notes for the current question; questions with no note attachments show no panel. Closing the notes panel alone keeps highlight mode active so further text can be annotated. It no longer opens a modal or a floating note editor. The panel can collapse without losing saved notes. After refresh, turn Highlights & Notes back on to reopen existing notes. Removing the final note hides the panel automatically. Existing general question notes remain accessible alongside attached notes when present. On small screens, the panel stacks within the question workspace.

`AnnotationToolbar.tsx` and `AnnotationToolbar.css` own the formatting palette, keyboard navigation, and viewport fitting. `NotesPanel.tsx` and `NotesPanel.css` own the inline cards and combined icon. `Player.tsx` anchors and saves annotations and note attachments; `RichText.tsx` reconstructs their color and underline style from immutable question text. Optional `Highlight.underlineStyle` and `Highlight.noteAttached` fields persist through the API and completed report, while older boolean underlines and nonempty notes still render. The answer eliminator uses an original crossed-out ABC icon; elimination remains independent of answer selection.

## Notes-panel resize handle

The passage and answer columns retain their original balanced layout. A compact black arrow handle appears just outside the notes panel, in the question margin, while attached notes are visible. Its visible grip is 16 by 30 pixels inside a larger 28 by 44 pixel drag target. Dragging it adjusts the notes rail and its cards; there is no independent passage/answer resize control. The panel remains hidden until Add note is used on selected text.

`NotesResizeHandle.tsx` and `NotesResizeHandle.css` implement pointer capture, sensible width limits, viewport adjustments and an accessible keyboard separator. Arrow keys change the notes width by 20 pixels, Shift+Arrow by 60, Home/End select the supported limits, and double-click restores the default notes width. `Player.tsx` stores the notes width locally for the attempt so refresh and close/reopen preserve it. On small screens, the workspace stacks vertically and the horizontal resize handle is hidden.

## Desmos calculator

`client/desmos.ts` defines the calculator bridge and API version. `Calculator.tsx` hosts the official Desmos Graphing Calculator in a sandboxed frame inside the movable/resizable Math tool. The separate document loads API v1.12 with the configured build-time key, resizes the graph with the panel and destroys it on close. Loading feedback is visible; network/script failures reset the loader and provide a local scientific/graph fallback plus Retry Desmos. The key is read from local environment configuration rather than copied into source code.
